# レポート: 判断パスカタログ — アナリスト暗黙知のAI再現に向けたアプローチ

**作成日**: 2026-04-10
**関連議論**: disc-2026-04-09-fm-an-perspective, disc-2026-04-10-an-seed-collection, disc-2026-04-10-judgment-path-catalog

---

## 1. エグゼクティブサマリー

本レポートは、優秀なアナリストの投資判断をAIで再現し、AN目線（推奨）とFM目線（批判）を統合した高パフォーマンスポートフォリオの構築を目指すプロジェクトにおいて、AN目線の形式知化手法として「判断パスカタログ」アプローチを採用した経緯と設計を記述する。

**結論**: AN目線の暗黙知は、明示的なルール集（dogma形式）ではなく、「アナリストの判断パス（入力→着目→結論）のカタログ」として蓄積し、類似事例検索（RAG）によりAIに再現させるアプローチが最適である。

---

## 2. プロジェクトの大目的

### 2.1 最終ゴール

```
優秀なアナリストたちの判断傾向をAIで再現
→ 大量の銘柄を分析（300-400銘柄ユニバース）
→ AN目線 + FM目線を組み合わせて
→ 優れたパフォーマンスのポートフォリオを複数作成
```

### 2.2 現状の課題

FM目線（dogma v1.0）は、投資仮説を批判的に評価するフィルタリング機能を提供する。しかし以下の限界がある:

| 機能 | FM目線（dogma） | AN目線（未構築） |
|------|----------------|----------------|
| 役割 | 投資仮説のフィルタリング | 投資前提（BUY理由）の発見 |
| 性質 | 減点法・チェックリスト的 | 加点法・創造的 |
| 出力 | 「この仮説は弱い/強い」 | 「この銘柄を買うべき理由」 |
| ポートフォリオへの貢献 | 「入れるべきでない銘柄」の除外 | 「入れるべき銘柄」の選定 |

**FM目線だけではポートフォリオ構築が困難**: 「何を買わないか」は分かるが「何を買うか」の判断基準が欠如している。

### 2.3 AN目線の位置づけ

AN目線の判断軸は、銘柄組入 → ポートフォリオ作成の判断過程で使用される。具体的には:

```
銘柄ユニバース（300-400銘柄）
    ↓
AN目線: 「この銘柄を買うべき理由はあるか」→ 組入候補を選定
FM目線: 「その理由は本当に堅牢か」→ 候補をフィルタリング
    ↓
複合スコアによるランキング → ポートフォリオ構築
```

## 3. FM目線とAN目線の構造的差異

### 3.1 初期認識（2026-03-17）

`analyst/memo/2026-03-17_discussion-and-next-actions.md` にて、アナリストYとの議論で以下が判明:

> 「FMが批判する目線とANが推奨ポイントを探す目線は異なる。現在のdogma/KBはFM視点寄り。」

### 3.2 構造的差異の詳細（2026-04-09 議論）

| 次元 | FM目線（批判） | AN目線（推奨） |
|------|--------------|--------------|
| **機能** | 仮説をフィルタリング | 仮説を発見・生成 |
| **評価方法** | 減点法（ルールに抵触したら減点） | 加点法（有望な材料を発見したら加点） |
| **形式** | ルールベース（判定型） | 経験ベース（直感・パターン認識） |
| **体系化状況** | dogma v1.0 完了（KB1: 8ルール, KB2: 12パターン, KB3: 5 Few-shot） | 未着手 |
| **思考プロセス** | 演繹的（ルール適用） | 帰納的（事例から判断） |

### 3.3 アナリストYの特性

Yとの議論で明らかになった重要な制約条件:

1. **フレームワーク非使用型**: 「私は入ってきた情報を分析して銘柄推奨のアウトプットを出すだけ」
2. **ロングオンリーファンド**: BUYの理由の設定が最重要。SELLは「もうBUYの理由がない」ことの確認
3. **暗黙知の本質**: Yの投資判断で未体系化なのは「投資前提をどう設定するか」— 大量の情報から何を選び、何を捨てるかの基準

```
Yの投資判断プロセス:
大量の情報 → [取捨選択（= 暗黙知）] → 投資前提の設定 → BUY/SELL
```

### 3.4 再帰的パラドックス

議論中に2度浮上した根本問題:

> 「AN目線をルール化すると、FM目線と同じ構造になるのでは？」

- 1回目（4/9）: 「AN目線をルールベースで書き起こしたら、それは別のdogmaに過ぎない」
- 2回目（4/10）: 「仮説に属性タグを付与して集計→ルール化するのは、結局FM dogmaと同じアプローチ」

この再帰的パラドックスが、判断パスカタログ方式の採用の直接的な動機となった。

## 4. AN目線の収集方法: 投資仮説Q&A

### 4.1 アプローチの設計

情報の閉鎖系（dogmaフィードバックループ）を回避するため、開放系アプローチを採用:

```
閉鎖系（問題あり）:
Y のロジック → AI が学習 → AI が Y のロジックで理詰め → Y 反論不能

開放系（採用）:
AI が新仮説を大量生成 → Y が直感的に反応 → パターンを蓄積
```

### 4.2 具体的な手法

SEC EDGAR + Earnings Call Transcriptから投資仮説候補を1銘柄あたり8件生成し、YにQ&Aシートで回答してもらう。

**仮説の粒度**: 「ある事業セグメントの成長率/利益率がX%になる具体的な理由」レベル（Yの過去23件の推奨レポートで確認された投資前提の粒度に合わせた）

**Q&Aシートの構造**:
```
冒頭: BUY/SELL総合判断欄 + 納得度スケール説明
ソース情報: 初期仮説構築期間 / 更新情報期間
仮説1-6: ポジティブ仮説（根拠情報テーブル + 更新情報 + 影響コメント + 納得度 + 備考）
仮説7-8: リスク仮説（同構造）
補足: SEC EDGAR財務サマリー（2期間）
```

**納得度スケール**: 90% / 70% / 50% / 30% / 10% の5段階

## 5. 形式知化アプローチの比較と選定

### 5.1 検討した3アプローチ

#### A. 明示的ルール化（AN版dogma）

dogma v1.0と同じ形式で、AN目線のルール集（KB4/KB5/KB6）を構築する。

```
KB4: AN目線のルール集（「Yはこういう仮説を高く評価する」）
KB5: AN目線のパターン集（高評価/低評価の具体例）
KB6: Few-shot（銘柄×仮説→納得度のYの実回答例）
```

**利点**: 透明性が高い。ルールが読めるため検証・改善が容易。dogmaと同じ構造のためca_strategy統合が容易。

**問題**: 再帰的パラドックスが再燃する。Yが「フレームワークを使わない」と明言している知識を、無理にフレームワーク化する矛盾。また、64データポイントから安定したルールを抽出するのは統計的に困難。

#### B. 例示ベース（判断例DB + in-context learning）

Yの実回答を大量にFew-shotとして与え、AIに「Yならどう判断するか」を推論させる。

```
プロンプト: 「以下はアナリストYが実際に評価した投資仮説と、
             その納得度です。これらの例から、Yの判断傾向を推論し、
             新しい仮説に対するYの納得度を予測してください」
           + Yの実回答例N件
```

**利点**: ルール化不要。LLMのin-context learning能力を活用し、暗黙的にパターンを学習。直感型アナリストに適合。

**問題**: 透明性が低い（AIが内部的にどのように判断を再現しているか不透明）。改善のフィードバックが困難。

#### C. ハイブリッド（判断例DB + 傾向サマリー）【採用】

判断例データベースを主要素とし、傾向サマリーを検証・透明性のための副次的出力として併用する。

**利点**: B案の利点（ルール化不要、直感型に適合）を維持しつつ、傾向サマリーで透明性を確保。属性タグは検索インデックスとして活用（ルールの条件部ではない）。

### 5.2 選定理由

| 評価基準 | A | B | C |
|---------|---|---|---|
| Yとの相性 | × | ○ | ○ |
| パラドックス回避 | × | ○ | ○ |
| 透明性 | ○ | × | △ |
| ca_strategy統合性 | ○ | ○ | ○ |
| スケーラビリティ | △ | ○ | ○ |

C案は、パラドックスを回避しつつ最低限の透明性を確保し、かつca_strategyに統合可能。

### 5.3 属性タグの役割転換

パラドックス回避の鍵は、属性タグの使い方の転換にある:

```
A案: タグ → 集計 → ルール
     （「Yは競争優位系の仮説を好む」= FM dogmaと同じ構造）

C案: タグ → 検索インデックス
     （「この仮説に似た過去のYの判断を検索する」= 事例ベース推論）
```

タグは「ルールの条件部」ではなく「検索のためのインデックス」として機能する。

## 6. 判断パスカタログ

### 6.1 概念

「判断パスカタログ」とは、アナリストごとの投資判断経路（どんなデータに着目し、どんな判断を下したか）を構造化して蓄積するデータベースである。

1銘柄分のアナリストの回答 = 1本の「判断パス」:

```
入力:  銘柄情報 + N個の投資仮説（各仮説に根拠データ付き）
       ↓
判断:  仮説1 → 納得度90%   ← どのデータに着目したか
       仮説2 → 納得度70%
       仮説3 → 納得度30%   ← どのデータを無視したか
       仮説4 → 納得度10%
       ...
       ↓
結論:  BUY / SELL + 備考（なぜそう判断したか）
```

### 6.2 データモデル（案）

```json
{
  "path_id": "jp-Y-ABBV-2026-04",
  "analyst": "Y",
  "ticker": "ABBV US",
  "company_name": "AbbVie Inc.",
  "sector": "Healthcare",
  "industry": "Biopharma",
  "date": "2026-04",
  "overall_judgment": "BUY",
  "overall_notes": "",
  "hypotheses": [
    {
      "hypothesis_id": 1,
      "text": "Humira特許切れ後もSkyrizi/Rinvoqの成長がBUYの根拠",
      "polarity": "positive",
      "tags": {
        "category": "competitive_advantage",
        "timeframe": "medium_term",
        "evidence_type": "transcript",
        "specificity": "quantitative"
      },
      "conviction": 90,
      "notes": ""
    }
  ],
  "metadata": {
    "initial_period": "2023-04 to 2025-01",
    "update_period": "2025-04 to 2026-02",
    "transcript_count": 11,
    "sec_filings_used": ["10-K", "10-Q"]
  }
}
```

### 6.3 アナリスト間比較

同一銘柄に対して複数アナリストのカタログが存在する場合:

```
Y のカタログ: 競争優位に90%、マクロに30% → BUY
Z のカタログ: 競争優位に60%、マクロに80% → SELL
```

→ アナリストの「目利き」の違いがカタログの差分として明示される。
→ 複数アナリストのスコアを統合 → チームとしての投資判断。

### 6.4 カタログの成長パス

```
Phase 1（現在）: 8銘柄 × Y = 8本の判断パス → パターンの方向を掴む
Phase 2: +12-22銘柄 × Y = 20-30本 → 初期予測力の検証
Phase 3: +70-170銘柄 × Y = 100-200本 → 安定したAN再現
Phase 4: + 他アナリスト → マルチアナリスト統合
```

## 7. ca_strategyへの統合設計

### 7.1 現在のパイプライン（FM目線のみ）

```
Transcript → 主張抽出 → 主張 × dogma(FM) → FMスコア
→ 銘柄レベル集約（StockScore）→ セクター中立化 → ランキング → ポートフォリオ
```

### 7.2 目指す姿（AN+FM複合）

```
Transcript → 主張抽出 ─┬→ 主張 × dogma(FM)     → FMスコア ─┐
                       └→ 主張 × 判断パスRAG(AN) → ANスコア ─┤
                                                              ↓
                                                    複合スコア
                                                              ↓
                                    銘柄レベル集約 → セクター中立化 → ポートフォリオ
```

### 7.3 ANスコアリングの具体的な処理

```
Step 1: 新銘柄の投資仮説に対して属性タグを付与
        （カテゴリ / 時間軸 / 情報源 / 具体性）

Step 2: 判断パスカタログから類似仮説のYの回答をN件取得（RAG）
        検索キー: 属性タグ + セクター + 仮説テキストの意味的類似度

Step 3: プロンプトにFew-shotとして埋め込み
        「アナリストYは以下のような仮説に対してこう評価しました。
         この新しい仮説に対するYの評価を予測してください。」

Step 4: LLMが予測納得度を出力 → ANスコア
```

### 7.4 複合スコアの設計（今後の検討事項）

FMスコアとANスコアの統合方法はいくつかの選択肢がある:

- **加重平均**: `複合スコア = α × FMスコア + (1-α) × ANスコア`（αは調整可能）
- **二段階フィルタ**: AN目線で組入候補を選定 → FM目線でフィルタリング
- **独立ポートフォリオ**: FM専用/AN専用/複合の3ポートフォリオを並列運用し、パフォーマンス比較

## 8. パターン抽出の手順（回答収集後）

### 8.1 事前準備: 仮説の属性ラベリング

生成済み8銘柄×8仮説=64仮説それぞれに属性タグを付与:

| タグ軸 | 値 |
|--------|-----|
| カテゴリ | 競争優位 / 市場拡大 / コスト構造 / M&A / マクロ / 規制 / リスク |
| 時間軸 | 短期(1-2年) / 中期(3-5年) / 長期(5年超) |
| 情報源 | Transcript / SEC Filing / AI推論 |
| 具体性 | 定量的 / 定性的 |

### 8.2 回答収集後のクロス集計

- カテゴリ別の平均納得度
- 時間軸別の平均納得度
- BUY銘柄 vs SELL銘柄での仮説採択パターン差
- 高納得度(90/70%)仮説の共通タグパターン
- 低納得度(30/10%)仮説の共通タグパターン

### 8.3 傾向サマリーの生成（副次的出力）

クロス集計から、検証・透明性のための傾向サマリーを生成:

```
例:
- Yは「競争優位 × 中期 × 定量的」な仮説に高納得度を付ける傾向（平均78%）
- Yは「マクロ × 長期」な仮説に低納得度を付ける傾向（平均35%）
- BUY判断の銘柄では、少なくとも2つの仮説が70%以上の傾向
```

これはルールではなく、カタログの品質チェックと人間の理解のための補助情報。

### 8.4 検証: 追加銘柄での予測力チェック

新しい銘柄でQ&Aを実施し、以下を検証:
- カタログのRAG検索が類似事例を適切に返すか
- AIの予測納得度とYの実回答の乖離度
- 収束するまで繰り返し
