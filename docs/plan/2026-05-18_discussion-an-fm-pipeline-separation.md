# 議論メモ: AN/FM パイプライン分離方針の確定 — 合流せず並行二本立て

**日付**: 2026-05-18
**議論ID**: disc-2026-05-18-an-fm-pipeline-separation
**前回議論**: disc-2026-05-11-feedback-loop-recap
**論点**: 論点A (FM フィードバックの判断パスカタログ統合方針)
**ステータス**: 決着

## 背景

2026-04-10 に「判断パスカタログ + RAG」方式が採用されて以降、当初設計では AN 目線 Q&A を主入力源とし、MCO/LRCX 等の FM フィードバックを「等価な入力」として統合する案が浮上していた。

2026-05-11 の認識合わせセッションで論点 A〜D が未決のまま持ち越されており、今回はその先頭の **論点A: FM フィードバックを判断パスカタログに統合する方針確定** を扱った。

## 議論の経緯

### 1. 進捗サマリーの確認

Neo4j (Discussion×多数, ActionItem×多数) と docs/plan の議論メモを横断的に参照し、プロジェクト全体の現在地を整理。AN 目線 Q&A は 8 銘柄完成・Y 回答は一部のみ、FM 目線は MCO Inverview が 2026-05-15 期限を超過した状態。

### 2. 統合 vs 分離の選択

最初の質問で「AN Q&A と FM Feedback を判断パスカタログでどう扱うか」を提示。
オプションは①共通スキーマ正規化、②別カタログ + 共通タグでメタ検索、③完全別パイプライン。

→ ユーザーは **③完全に別パイプライン** を選択。

### 3. ユーザー意図の明確化

ユーザー発言: **「AN 目線のアナリスト Y からのデータ収集と、FM 目線のそれとは分離して別々に実行したい」**

→ データ収集プロセス自体を分離する意思を明示。Y への提示資料・収集スケジュール・運用フローを共通化しない。

### 4. 合流点の確認

下流処理の合流点を 3 択で提示。①ca_strategy のスコア統合層、②RAG ストレージ層でマージ、③合流せず並行二本立て。

→ ユーザーは **③合流せず並行二本立て** を選択。

→ 判断パスカタログという当初コンセプト（統合 RAG）は実質的に廃案。AN_Catalog / FM_Catalog は別物として独立運用。
