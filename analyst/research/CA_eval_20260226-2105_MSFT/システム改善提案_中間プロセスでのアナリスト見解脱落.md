# CA-eval システム改善提案：中間プロセスにおけるアナリスト見解の脱落問題

> **作成日**: 2026-06-05
> **対象システム**: ca-eval（競争優位性評価）ワークフロー
> **起因ケース**: CA_eval_20260226-2105_MSFT / 主張#2「Azureクラウドプラットフォーム」
> **関連**: `Feedback_MSFT.md`（アナリスト指摘）, `revised-report-MSFT.md`（最終版）
> **調査根拠**: 全中間ファイル（01〜04）のデータフロー追跡 + ca-eval 実装（SKILL.md / agents / schemas）の精読

---

## 1. エグゼクティブサマリー

ca-eval ワークフローにおいて、**アナリストレポートの定性的・比較的な核心見解が中間ファイル作成プロセスで脱落し、最終評価で正反対の結論を生む**構造的欠陥が発見された。

**ケース**: MSFT Azure（主張#2）で、アナリストが明言した
> 「Azureの成長 = クラウド市場成長(LDD) + **シェアゲイン**(MDD) = **市場アウトパフォーム**」「Others がシェア喪失する構図」

という見解が、T4（claims.json）では CAGR confidence 70% の根拠として正しく保持されていたにもかかわらず、T8（AI批判）で
> 「その成長がMSFT固有の構造的優位性に基づくのか**市場全体の成長なのかが不明確**」

と**反転**され、CAGR が 70%→50% に引き下げられた。アナリスト自身も `Feedback_MSFT.md` で「『市場成長以上のIC事業売上CAGR＠6/13/24』とのAN見解が見落とされているのでは？」と同一点を指摘している。

**根本原因は T7→T8 境界の設計**にある。元見解を保持していた `claims.json` が T8 の視野に入らず、T8 が読む `structured.json` のスキーマには元見解フィールドが存在しないため、AI批判は「アナリストが既に明言済みの見解」を認識できないまま、しばしば否定方向に再評価する。

## 2. 問題の発見：ケーススタディ（MSFT Azure 主張#2）

アナリスト見解「市場成長を上回るシェアゲイン」が各段階でどう扱われたかを追跡した結果。

| 段階 | ファイル / 生成主体 | シェアゲイン見解の扱い | 状態 |
|------|--------------------|----------------------|------|
| ① 原本 | parsed-report.json / **T2 ca-report-parser** | `source_text` に「シェアゲイン継続（Others がシェア喪失する構図）」。ただし比較命題は `factual_claims[]` に構造化されず自由テキストに埋没 | ⚠️ 半構造化 |
| ② 主張抽出 | claims.json / **T4 ca-claim-extractor** | `cagr_mechanism`:「クラウド市場CAGR LDD+シェアゲインでMDDの市場アウトパフォーム想定」。`cagr_confidence` 70% の reasoning:「過去実績（Azure +30%超を複数年維持）と整合」 | ✅ 明示保持・採用 |
| ③ 事実検証 | fact-check.json / **T5 ca-fact-checker** | 検証対象は Azure +39%・市場2位・$75bn 等の**数値事実のみ**（全て verified）。「シェアゲイン／市場成長超過」命題は検証対象リストに**存在しない** | ❌ 命題が脱落 |
| ③ パターン検証 | pattern-verification.json / **T6 ca-pattern-verifier** | CAGR接続評価では痕跡保持（「シェアゲイン…過去実績と整合」moderate）。だがCA本体ではパターンA「シェアゲイン継続は"結果"」+ パターンG（strong）「純粋競合に対する優位性不明」で**弱点化** | ⚠️ CAGR側に痕跡 / CA側で否定的 |
| ④ 構造化 | structured.json / **T7 ca-report-generator** | スキーマに `source_text`/`cagr_mechanism`/`description` が**無い**。元見解は `key_evidence`（数値要約5件）に縮約され消失 | ❌ スキーマ上消失 |
| ④ AI批判 | critique.json / **T8 Lead直接実行** | 入力が `draft-report.md`+`structured.json`+KB に限定され、claims.json を読まない。「市場成長か固有か不明確」として CAGR 70%→50% | ❌ 見解を参照せず反転 |
| ④ 最終版 | revised-report-MSFT.md / **T8 Lead** | 「成長がMSFT固有の優位性か市場成長かの区別が不明確」（claim#2 CAGR接続） | ❌ アナリスト断定の正反対 |

**核心**: アナリストは「市場成長 **か** 固有 **か**」という未解決の問いではなく、「市場成長を **上回る** シェアゲイン（固有のアウトパフォーム）」と**断定**し、その根拠（過去実績 Azure +30%超×複数年）も示していた。T8 はこれを「不明確」と未解決扱いで棄却した。

## 3. 根本原因分析（実装レベル）

### 原因①【決定的】T7→T8 境界でのスキーマ情報欠落

T8（AI批判）が読む `structured.json`（T7生成）のスキーマ（`templates/schemas/structured.schema.md`）の claims[] 利用可能フィールドは：

```
claim_id, title, ca_type, final_confidence, label, cagr_confidence, cagr_label,
fact_check_status, rule_summary, patterns_detected, key_evidence,
upside_conditions, downside_risks, note
```

→ **`source_text` も `cagr_mechanism` も `description` も無い**。元見解は T4（claims.json）で `cagr_mechanism`/`source_text` に保持されていたのに、T7 で structured.json へ再構成される際に脱落し、`key_evidence`（数値要約）に縮約される。

### 原因②【決定的】T8 入力スコープの限定

`ca-eval-lead.md` のT8セクション（L742）で入力が固定されている：
> 「入力: draft-report.md, structured.json, KB1-KB3（全26ファイル）, dogma.md」

→ 元見解を持つ唯一のファイル（`claims.json` の `cagr_mechanism`）も、原本（`parsed-report.json`）も**T8の視野外**。T8セクション全体（L734-827）に claims.json / parsed-report.json / source_text への参照は一切ない。

### 原因③【決定的】批判ロジックの非対称性

T8 は「KB基準 vs 下流の数値要約」だけで批判するため、**アナリストが既に明言済みの見解を新規の論点として再発見し、否定方向に倒す**。MSFT Azure では「市場か固有か不明確」と反転した。「CA50%とCAGR70%の整合性」という機械的調整が、元見解の検討より優先された。

### 原因④【補強脆弱性】fact-check が数値事実のみを扱う

`ca-fact-checker.md`（L12）のミッションは `factual_claim`（数値・データ）の SEC 照合のみ。「市場成長を上回るシェアゲイン」のような**比較的・定性的命題を検証/保持する経路が定義されていない**。fact-check.schema には `source_text`/`cagr_mechanism` も無いため、定性見解は Phase3 で一度も「保護」されないまま T7 の縮約に至る。

### 原因⑤【上流潜在要因】parsed-report が比較命題を構造化しない

T2（ca-report-parser）は parsed-report.json で、定性的比較命題（「市場成長以上のCAGR」）を独立フィールド化せず、`source_text` 自由テキストと数値中心の `factual_claims[]` に分散させる。比較・定性命題が最初から構造化されないため、下流で機械的に追跡できない。

### 原因⑥【監査不能】confidence 調整の元見解トレース欠如

各段階に confidence 引下げの理由記録（`reason`/`reasoning`）はあるが、すべて `claim_id` 参照のみ。`critique.schema` には KB 側根拠の `kb_reference` はあっても、**元レポート側根拠の `source_reference` が無い**。「アナリストが明言したどの見解を AI が棄却したか」を突き合わせるフィールドがなく、見解の棄却が監査できない。

### 原因⑦【検出不能】脱落チェックの不在

全 ca エージェント・lead・スキーマのバリデーションルールを横断調査した結果、**元レポートの主張が下流に伝播しているか検証するステップは設計に一切存在しない**。`claims.schema` のバリデーション（主張5-15件、形式チェック等）は構造検証に留まり、内容の継承は検査対象外。

## 4. 影響範囲（一般化リスク）

本問題は MSFT Azure に限定されない、ca-eval の**構造的欠陥**である：

- **全銘柄・全主張に波及**: T7→T8 のスキーマ・入力設計は銘柄非依存。定性的・比較的な見解（「競合Xを上回る」「市場平均以上」「シェアを奪う」等）を持つ主張は、すべて T8 で脱落・反転しうる。
- **特に高リスクな主張類型**: ①競合比較を伴う成長主張（シェアゲイン）、②定性的な質的優位（ブランド、文化、経営力）、③「市場/業界平均との差分」で語られる主張。これらは数値1点では表せず fact-check で保護されないため脱落しやすい。
- **評価の系統的バイアス**: T8 は「下流の数値要約 vs KB」で批判するため、定性的な強みを持つ主張ほど不当に低評価される傾向（confidence 引下げ方向の偏り）。

## 5. 改善提案（優先度・実装マッピング付き）

### 最小介入セット（高優先・即効性）

| ID | 提案 | 対象ファイル | 具体的変更 | 工数 |
|----|------|------------|-----------|------|
| **A** | structured.json に元見解保持フィールド追加 | `templates/schemas/structured.schema.md`, `ca-report-generator.md` | claims[] に `analyst_view`（必須）を追加。`source_text` 要約 + `cagr_mechanism` 全文を転記。T7 が claims.json から無損失でコピーする指示を明記 | 小 |
| **B** | T8 入力に claims.json を追加 | `ca-eval-lead.md`（L742 入力定義） | T8 入力を「draft-report.md, structured.json, **claims.json**, KB, dogma.md」に拡張。「confidence を引き下げる前に、対象 claim の `cagr_mechanism`/`source_text` を確認すること」を必須手順化 | 小 |
| **C** | critique に元見解整合チェックを必須化 | `templates/schemas/critique.schema.md`, `ca-eval-lead.md` T8手順 | claim_critiques[] に `source_reference`（棄却/採用した元見解の逐語引用）を必須追加。**ルール: 「元レポートの明示的見解と矛盾する批判を行う場合、その見解を引用し、なぜ棄却するかを `source_reference` に明記する」**。引用なしの反転的批判を禁止 | 小〜中 |

> 提案 A+B+C を入れていれば、MSFT Azure のケースでは T8 が「アナリストは『シェアゲインで市場アウトパフォーム（過去実績 Azure +30%×複数年）』と明言している」を必ず認識し、CAGR 引下げには「シェアゲインは事実だが AWS/GCP に対する構造的優位の定量証明が不足」という**正確な根拠**を `source_reference` 付きで記す必要があった。「市場か固有か不明確」という反転は構造的に起こり得なくなる。

### 補強セット（中優先）

| ID | 提案 | 対象ファイル | 具体的変更 |
|----|------|------------|-----------|
| **D** | fact-check に定性・比較命題カテゴリを追加 | `ca-fact-checker.md`, `fact-check.schema.md` | `factual_claims_checked` とは別に `qualitative_claims_checked[]`（比較命題: 「市場成長を上回る」等）を新設。SEC/開示データで「検証可能/部分的/検証不能」を判定し、定性見解を Phase3 で保護 |
| **E** | parsed-report に比較命題の構造化フィールド | `ca-report-parser.md`, `parsed-report.schema.md` | ca_candidates[] に `comparative_thesis[]`（「対○○で優位」「市場平均比で△△」等の比較命題を抽出）を追加。上流で比較命題を独立追跡対象にする |
| **F** | 脱落チェックステップの新設 | `ca-eval-lead.md`（T7後 or T8前）, 新スキーマ | T8 実行前に「claims.json の各 `cagr_mechanism`/比較命題が structured.json または critique で言及されているか」を機械的に照合する検証ステップを追加。未言及の見解を warning として列挙 |

### 横断改善（低優先・恒久対策）

| ID | 提案 | 内容 |
|----|------|------|
| **G** | confidence 監査証跡の標準化 | 全段階の confidence 調整記録に `source_reference`（影響した元見解）を付与。「どの元見解の採用/棄却が confidence を動かしたか」を end-to-end で追跡可能にする |
| **H** | 設計原則の明文化 | `ca-eval/SKILL.md` に「**アナリストの明示的見解は、棄却する場合も必ず引用した上で棄却理由を示す（暗黙の脱落を禁止）**」を全エージェント共通原則として追記。ca-claim-extractor の既存原則「主張は破棄しない」を下流全段階に拡張 |

## 6. 実装ロードマップ

```
Phase 1（即効・最小介入）: A → B → C
  structured.schema に analyst_view 追加 → T8入力に claims.json 追加 → critique に source_reference 必須化
  ※ この3点だけで MSFT 型の反転は構造的に防止可能

Phase 2（保護層強化）: D → E → F
  fact-check に定性命題カテゴリ → parsed-report に比較命題構造化 → 脱落チェックステップ新設

Phase 3（恒久・横断）: G → H
  監査証跡標準化 → 設計原則の明文化
```

**回帰検証**: 改善後、本 MSFT ケース（CA_eval_20260226-2105_MSFT）を再実行し、主張#2の T8 critique が「シェアゲイン見解を引用した上で評価」する形に変わること、CAGR 評価の根拠が「市場か固有か不明確」ではなく「シェアゲインは事実／構造的優位の定量証明が課題」に修正されることを確認する。
