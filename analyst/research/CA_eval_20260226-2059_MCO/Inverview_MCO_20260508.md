### 評価フレームワーク：保守性≠確度の原則（claim#2 関連）

#### 背景・問題意識

revised-report-MCO.md の claim#2「プライシングパワー」の AI 評価ロジックに対し、フィードバックで以下の根本的批判を頂いた:

> 「予想の保守性、楽観性とも公平に評価されるべき『幅』であり、保守的という時点で最適推量でないということ。あくまで最適推量の結果に対しての納得度評価をすべきであり、保守的故に確度が高まるとの評価は妥当でない」

> 「業績予想の保守性は特にセルサイドで散見されることであるが、ＢＵＹ推奨への援護的（市場予想未達だった時に、私の予想に対しては過達であった/超過したときに、私の予想を大きく上回ったなど）側面強く評価しない」

該当箇所:
- claim#2 CAGR接続 90%: 「価格効果+2.5%は過去実績+4-5%に対し保守的な+2.5%で達成確度高い」
- 自社株買い +1.5%: 「FCF利回り3%（従前+2%から引き下げ）」← 保守化された値
- claim#5 CAGR 50%: 「アナリスト自身がCAGR引き上げを見送っている」← アナリスト自身の保守性を確度根拠化

#### 批判の構造分解（3層）

| 層 | 主張 | 射程 |
|---|------|------|
| L1: 認識論 | 評価対象は「最適推量」（期待値）であるべき | 全 CAGR / claim 評価 |
| L2: ロジック | 保守的＝最適推量から外れている → 確度を高める根拠にならない | confidence 算定方法 |
| L3: 動機論 | 保守性はセルサイドの BUY 推奨援護バイアス | アナリストレポート採用方針 |

#### この原則の帰結

確率分布のメンタルモデルで整理すると:

```
CAGRの真の分布 ~ N(μ, σ²)

AI現行: estimate = μ - α (保守側) → 「達成確度高い」と評価
AN原則: estimate = μ (最適推量) → estimateの妥当性を confidence で評価
                              σ (不確実性) は別軸で評価
```

帰結1: CAGR estimate +2.5% が保守的なら、最適推量 +4-5% に upgrade すべき。confidence はその +4-5% への納得度評価。
帰結2: AI が「保守的だから安全マージン」として高 confidence を付与している箇所は、すべて再算定対象。
帰結3: KB ルール（dogma.md）に「保守性は confidence の加点要因にならない」を明記する必要。

仮に AN 原則で MCO の CAGR を再算定すると、EPS CAGR 9.5% → +1.0〜+1.5pt 上方修正の可能性がある。

#### Q-A1: confidence の定義の明文化

**質問の意図**: AI 評価フレームワークの根幹である「confidence」の定義を、AN 原則と整合させる必要がある。現行は「達成確度」（保守的なら高い）として運用しているが、AN は「最適推量への納得度」を評価軸とすべきと指摘。これは confidence の運用ロジックの根本的な転換であり、明確化が必要。

- (a) confidence = 最適推量への納得度 という再定義で正しいか？
- (b) その場合、不確実性（レンジ・ボラティリティ）は別軸として導入すべきか？それとも confidence に統合すべきか？
- (c) confidence と「達成確度（リスク調整後）」を分離する必要はあるか？分離する場合、後者はどう運用するか？

**背景**: 現行 dogma.md では confidence の定義が「主張の納得度」と曖昧で、保守性をプラス要因として扱う余地があった。AN 原則を採用すると、confidence は estimate の中央推定としての妥当性のみを評価し、リスクは別指標になる。

### 評価フレームワーク：定量データ vs 論理整合性（claim#4 関連）

#### 背景・問題意識

revised-report の T8 批判で、claim#4「MAデータ蓄積」と KB3 の COST「思いやり経営」を比較し、「MCO は各ステップに定量データ（クロスセル2割、維持率93%、ARR+8%）が存在する点で COST よりマシ」と評価した。これに対し AN は以下を明示:

> 「T8批判でくりかえす COST の飛躍とは、従業員離職と顧客サービス、顧客サービスと既存店売上、各々の関連が弱すぎるということ。顧客サービスを決定する要素は、従業員の教育レベル、適切な顧客接触などであり、離職率そのものが決定的要素とはならない。既存店売上の決定要素も、来客頻度、来客当たり購買額などであり、商圏魅力度、品ぞろえなどがその決め手となる。従業員サービスレベルが既存店売上に与える影響は小さい」

> 「T8評価にあるように、クロスセル２割、維持率93％のような定量的データをもって納得を高めているのではなく、要素の重要性や論理の整合性への妥当性がCOSTは低く、ＭＣＯは高いということ」

#### 批判の本質

AI フレームワーク現行: ルール4「定量的裏付け」を主軸に、定量データの有無で confidence を判定。
AN 原則: **「論理連鎖の各ステップで、原因要素が結果を実質的に決定するか」** で判定。定量データはあくまで裏付けであり、論理整合性が成立していない場合はデータがあっても無意味。

具体例:
- COST「離職率 9%」は事実だが、「離職率→既存店売上」の論理連鎖は弱い（決定要因は商圏・品揃え）→ データがあっても confidence は上がらない
- MCO「クロスセル 2割」は事実、かつ「データ蓄積→クロスセル→ARPU→CAGR」の論理連鎖は妥当 → confidence が上がる

つまり評価軸は **論理整合性が一次的、定量データは二次的（補強材料）**。

#### Q-B1: 評価軸の優先順位

**質問の意図**: 現行 AI フレームワークはルール4（定量的裏付け）を強い PASS/FAIL 基準として運用してきたが、AN 原則ではルール4 単独で評価せず「論理整合性が前提」となる。優先順位の明文化が必要。

- (a) 評価ロジックは「論理整合性が成立 → 定量データで補強」という二段階構造で運用すべきか？
- (b) 論理整合性が弱い場合、定量データがどれだけ豊富でも confidence は一定以上に上がらないというキャップを設けるべきか？（例：論理整合性 NG なら confidence 上限 30%）
- (c) 逆に、論理整合性が極めて強い場合、定量データが不足していても高 confidence を与えてよいか？閾値はどの程度か？

**背景**: 現状ルール4 が PASS だと自動的に 70-90% の confidence に寄りやすい運用バイアスがあった可能性。論理整合性の優位を明文化する必要。

#### Q-B2: 論理整合性の評価基準

**質問の意図**: 「論理整合性が高い」「弱い」を AI が機械的に判定するためには、評価基準の明文化が必要。AN コメントから読み取れる判定基準を具体化したい。

- (a) AN が COST「離職率→サービス→既存店売上」を「弱い」と判定した基準は以下のどれに近いか？
  - 原因要素が結果を決定する寄与度の小ささ（他要素の影響が大きい）
  - 因果関係の介在ステップが多すぎる
  - 因果関係に逆向きの作用も存在する（例：離職率の低い企業はコスト過剰）
  - 定量的に検証された事例の不在
- (b) 論理整合性を判定する際、**「結果を決定する真の要素を列挙し、当該要素の寄与度を評価する」** という手順を AI に組み込むべきか？
- (c) 「決定要素の寄与度評価」を AI 単独で行うのは難しい場合、AN への確認プロセスを組み込むべきか？

**背景**: AN コメントは「結果の決定要素は X, Y, Z であり、評価対象 A はその一部にすぎない」という構造。AI がこの種の判定を再現するには、業界知識と決定要素マッピングが必要。

  - KYCクロスセル→ARPU：強（クロスセルがARPUを直接押し上げる）

#### Q-B4: ルール4「定量的裏付け」の再定義

**質問の意図**: dogma.md のルール4 は現状「定量的裏付けの有無」を判定するが、AN 原則を反映するには再定義が必要。具体的な改訂方針を確認する。

##### 現行 dogma_v1.0.md ルール4 の記述

> **ルール 4: 優位性の説明力が評価の基盤（定量はWANT、説明力がMUST）**
> - **良い例:** COST#1（退職率9% vs 業界20%+: 70%）— 定量裏付け+説明力あり
> - **悪い例:** COST#2（「劇場型」のみの説明: 10%）— どんな売り場づくりかの説明が不足

##### 規定と運用の乖離

ルール4 のテキストは既に「**説明力が MUST、定量は WANT**」と明示しており、AN 原則と整合的。しかし revised-report-MCO.md の T8 評価では:

- claim#4 のルール適用マトリクス（line 192-202）で **「ルール 4. 定量的裏付け: PASS（クロスセル2割、ARR、維持率）」** と記述。
- T8 注4（line 186-189）で「MCO は各ステップにデータが存在するため因果飛躍度は COST より低い」と、**定量データの存在を主たる根拠** として COST との差を説明。

つまり **規定上は説明力 MUST だが、運用では定量データ PASS が主要シグナルになっていた** 可能性が高い。AN 批判は「規定通りに説明力（論理整合性）を一次評価せよ」という運用是正の指摘とも読める。

##### 質問

- (a) ルール4 の **テキスト自体は AN 原則と整合** しているとの理解で正しいか？問題は運用側にあり、ルール文言の改訂よりも **「説明力＝論理整合性」の判定手順を運用ガイドに追記する** 方向で十分か？
- (b) もしルール4 を再定義する場合、現行の「説明力 MUST、定量 WANT」を **より強い表現** に書き換える案は妥当か？（例：「論理整合性が不成立なら定量データの有無に関わらず confidence 上限 30%」とキャップを明示）

#### 論点間の関係性

| 論点 | 影響範囲 | 解決の優先順位 |
|------|---------|--------------|
| A: 保守性≠確度 | confidence 算定方法の根幹 | 最高 |
| B: 定量 vs 論理 | ルール4 の再定義、KB3 全体への波及 | 高 |
| C: 事業構成ブレンド | 評価単位（claim 単位 vs セグメント vs 全社） | 高 |
| D: ブランド独立性 | ダブルカウント / フィードバックループの判定 | 中 |
| E: 機会と優位性 | claim 構成の妥当性、削除/統合の判断 | 中 |

A → B → C の順で固めると、D と E は論理的に派生する関係。AN 確認の順序として、論点 A → B → C → D → E が効率的と考える。
